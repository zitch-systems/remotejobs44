# RemoteJobs44 — Production Audit (July 2026)

End-to-end audit across security, API correctness, database/RLS, UI/UX,
accessibility, SEO, and performance. Baseline was healthy (TypeScript clean, 493
unit tests green, production build passing, ESLint 0 errors); the platform is
unusually well-hardened, with many deliberate, well-commented trade-offs. This
pass fixed the genuine defects found and left stable modules untouched.

## Production readiness

**Ready.** No critical or high-severity security defect survived verification.
The fixes below close one real focus-loss bug in the admin console, a
double-submit hazard, a billing downgrade race, two defense-in-depth SSRF gaps,
and several SEO/accessibility issues. Remaining items are documented, low-risk,
and mostly operational (schema-file hygiene).

## Fixes applied

### Correctness / functional
- **Admin "Post New Job" form lost focus on every keystroke.** `Field` was
  declared inside `NewJobPage`, so each render produced a new component identity
  and React remounted every input, blurring the focused field after each
  character. Hoisted `Field` to module scope. (`app/admin/jobs/new/page.tsx`)
- **JobCard Apply double-submit.** The Apply handler had no in-flight guard, so a
  rapid double-tap fired two `apply` POSTs, double-counted the Day Pass quota,
  and opened two tabs before `applied` flipped. Added a `useRef` re-entrancy lock
  around the async apply path. (`components/jobs/JobCard.tsx`)
- **Billing downgrade race in the expiry cron.** `expire-daily` did
  SELECT-then-blind-UPDATE, so a Paystack renewal landing mid-sweep could still
  force `plan='free'`. Converted both the daily and pro branches to
  compare-and-set (`UPDATE … WHERE <expiry predicate> RETURNING`), so a
  concurrently-renewed row is excluded from downgrade.
  (`app/api/cron/expire-daily/route.ts`)

### Security
- **SSRF: DNS-aware guard on two secondary fetch paths.** Feed discovery
  (`tryDiscoveredFeeds`) and direct-apply enrichment (`enrichDirectApplyLinks`)
  validated externally-derived URLs with the string-only guard, which a public
  hostname resolving to an internal IP defeats. Both now use
  `validateExternalUrlAndResolve` (DNS resolution + private-IP rejection),
  matching every other externally-influenced fetch in the codebase.
  (`lib/feed-discovery.ts`, `lib/apply-link.ts`)

### Database (migration `v62` — needs applying)
- **jobs RLS leaked flagged + expired rows via direct REST.** The public SELECT
  policy filtered only `is_active`; flagged (scam-suspected) and expired rows
  were reachable through anon PostgREST because the flagged/expired predicates
  lived only in app query code. The policy now enforces the app's exact
  visibility invariant (NULL columns stay safe; admin/service reads unaffected).
- **profiles privilege-escalation guard.** `profiles_update` has no `WITH CHECK`;
  self-elevation is blocked today only by column-level GRANTs. Added a
  `BEFORE UPDATE` trigger that rejects changes to `role`/`plan`/`plan_expires_at`/
  `suspended` from authenticated end-users (service role + direct DB exempt), so
  security no longer rests solely on the GRANT set.
- **Missing index** on `subscriptions.paystack_subscription_code`, used by the
  `invoice.payment_failed` webhook lookup on the billing hot path.

### SEO
- **`/api/og` was blocked by robots.txt.** Every page's `og:image`/`twitter:image`
  resolves to `/api/og?…`, so Twitter/X and LinkedIn card scrapers refused the
  image. Added an `/api/og` allow that wins under longest-match precedence while
  the rest of `/api/` stays blocked. (`app/robots.ts`)
- **JobPosting JSON-LD emitted an empty `description`** for listings with no
  scraped body, which makes Search Console drop the rich result. Synthesize a
  minimal valid description in that case. (`app/jobs/[id]/page.tsx`)
- **Duplicate title/H1** on `/jobs/region/worldwide` vs `/jobs/country/worldwide`.
  Canonicalized the region variant onto the country one to consolidate the
  duplicate. (`app/jobs/region/[slug]/page.tsx`)
- **`/settings` used a 307 redirect** while documented as permanent. Switched to
  `permanentRedirect` (308) so link equity consolidates onto `/profile`.
  (`app/(member)/settings/page.tsx`)

### UX / accessibility
- **`/interview-prep` lacked the member auth gate** its sibling tool pages use, so
  logged-out visitors saw member chrome before the redirect. Added
  `useMemberGate()` for parity. (`app/(member)/interview-prep/page.tsx`)
- **Low-contrast informational text in JobCard.** Location/timezone/posted-date
  used `text-stone-400` (~2.6:1, WCAG AA fail). Bumped the info lines to
  `stone-500` (~4.6:1). (`components/jobs/JobCard.tsx`)

## Notable items left as-is (documented, lower priority)

- **Schema-file divergence** (`supabase/schema.sql` vs `setup.sql`) and duplicate
  column definitions across migrations make the live DB shape order-dependent.
  This is a hygiene/reproducibility issue, not a runtime defect — consolidating
  to one canonical bootstrap is recommended but out of scope for a surgical pass.
- **Performance micro-optimizations** (per-category count queries on the home
  page, distinct-company estimate on `/about`, top-company scan for the sitemap)
  are all ISR-cached and low-impact; converting to `GROUP BY` RPCs is a nice-to-
  have.
- **A fuller color-contrast sweep** beyond JobCard (dashboard/applications/saved
  secondary labels) is recommended as a design-reviewed change.
